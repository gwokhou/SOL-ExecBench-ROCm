# E2 LayerNorm 研究参考的 CPU 验收

2026-11-19。显式选择 `centered_fp64_v1` 时，研究 staging 使用中心化的双遍 FP64 均值和总体方差，按实际 FP32 epsilon 和 affine 计算，最后舍入 FP32。同一参考源码用于该版本的 P0 等价对照，P1、P2、P3 沿用原候选源码。原 E2 运行入口仍默认使用原参考，正式评分路径与原容差保持原样。 [参考实现](../../scripts/internal/solar/e2_layernorm_reference.py) · [研究 staging](../../scripts/internal/solar/e2_staging.py)

## 留存证据验收

在 CPU 上从带 SHA-256 的留存文件读取同一份量化输入，调用新 staging 提供的参考，逐元素比较已认证区间 oracle 的 FP32 舍入结果。再用原数值比较器检验保存的候选输出。验收覆盖了 LayerNorm 的 144 个逻辑单元、432 个正确性会话内的全部 3,669 个留存调用。因提前拒绝而未执行的调用保持原状态。

| 验收项 | 结果 |
| --- | --- |
| 新参考与留存 oracle | 3,669/3,669 逐元素精确相等，覆盖 L0 的 648 次、L1 的 915 次、L2 的 1,188 次和 L3 的 918 次 |
| 原 90 个不确定对照 | 568/568 个已留存的正确性调用满足 4 ULP，且精确相等 |
| 历史计时拒绝 | 正确性活动中 3/3、成本侧 2/2 在保存输入上的数值比较通过，最小容差余量均约为 1.25038e-5 |
| L1/P2 的真实越界 | 原先拒绝的 7/7 和原先被掩盖的 1/1 均被检出 |
| LayerNorm 负对照 | L0/P2 方差见证 27/27、L3/P1 必检违例 27/27 继续拒绝 |

逐调用记录带原输入、观测、会话及冻结身份的 SHA-256。原始判定、90 个不确定会话和 15 个重复不一致单元均保留。原 E2 的 432 个总逻辑单元、1,296 个正确性会话、144 个成本会话、72 个离线回放和裁判未达标结论继续作为历史记录。 [CPU 对照收据](../../data/outputs/solar-e2-layernorm-reference-cpu-20261119/retained-call-comparison.json) · [原 E2 收尾](solar-e2-successor-results-2026-11-19.md)

## CPU 接入与后续验收

CPU 开发夹具核对了 P0 的打包源身份、P1/P2/P3 原源码、独立的受信计时校验，以及真实越界输出仍被拒绝。新的 GPU 整链验收需先登记专用规格与执行身份，绑定参考选项、参考源码、P0 源码和原数值检查。开发输入上的同字节重复与跨置换一致性分开检验，P0/P3 均须通过原容差和完整计时验真，P1/P2 继续作负对照。首批假设验证使用开发输入。历史留出已暴露，后续确认需新冻结和独立留出。
