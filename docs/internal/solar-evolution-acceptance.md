# SOLAR 演进：阶段 0 验收样本清单

规格冻结日期：2026-10-20；执行状态更新：2026-10-26。配套[能力／假设／基线](solar-evolution-stage0.md)和[任务规格](solar-evolution-tasks.md)。可执行样本及 CPU 观察已在 BASE-01 落地，详见[改进前基线](solar-base01-cpu-2026-10-23.md)与[当前工作树复采](solar-base01-cpu-2026-10-26.md)；下列数学目标保持原值，不因当前实现的差异而修改。

## 1. 分母、角色和状态

四组分母独立报告，不合并成一个“覆盖率”：

| 组 | 固定分母 | 用途 | 当前状态 |
| --- | --- | --- | --- |
| F：语义与计量样本 | 8 个族 × D/Q 两个实例 = 16 个具体程序实例；每实例分别请求两条路径，共 32 个路径槽位 | D 用于开发；Q 用于规则冻结后的回归资格检查 | fixture 已实现；32 已尝试，30 验证／计量完成、2 转换拒绝；当前保留 4 条 F04 差异，原始基线的 8 条差异不覆盖 |
| G：静态访问 oracle | G01–G10，共 10 个几何／拒绝场景 | 不依赖 torchview 或生产并集算法的独立集合枚举 | 独立 oracle 已检查；BASE-01 不评估后续生产能力，记录为 `not_evaluated` |
| M：模型与复用合同 | M01–M10，共 10 个验收规格；实现可进一步参数化，但不得减少场景 | 三视图、反向查询、失效、资格与预算 | 6 个数值／定义域 oracle 已检查，4 个合同 fixture 已落地；本轮生产接口验收为 `not_evaluated` |
| R：仓库真实输入 | R01–R08，共 8 个固定 UUID；两条路径共 16 个槽位 | 真实图形回归与失败归因；不是全部 corpus 或旧 41-workload 分母 | 输入身份已复核；16 槽位仍为 `not_run` |

Q 是预留回归实例，参数公开且未声称统计独立／盲测；不能据此宣称泛化成功率。后续若开展模型拟合或 LLM 泛化评估，应另外冻结未暴露的 held-out 集，不复用这里的 Q。

每个槽位都保留结果，即使 extractor 不支持。报告至少区分：未执行、提取失败、转换拒绝、验证失败、计量不可用、计量完成、正式资格结果。真实错误码复用现有 registry；本表的状态文字不是新增 wire 值。`BASE-01` 在修改实现前记录每条路径的实际状态，不预先假定全部成功。

本轮代码入口为 [F 样本](../../scripts/internal/solar/base01_samples.py)、[G/M oracle 与合同 fixture](../../scripts/internal/solar/base01_oracles.py)和[CPU 采集器](../../scripts/internal/solar/run_base01_cpu.py)。G 的数学集合、M 的公式自检不作为阶段 1–3 功能通过记录；M03/M04/M05/M10 仅有明确合同输入，真实 mapper／复用／扫描接口验证仍待后续实现。

## 2. F 组：具体程序规格

共同设置：独立输入存储，除特别注明外使用连续布局；当前两条 `IRPath` 分别执行，不能自动换路。trace seed 固定 200；使用冻结源码中的 `ConversionRequest` 默认验证策略并把完整策略序列化进基线（当前为 11/29/47 三 seeds、random/zeros/boundary，默认检查梯度）。精度、设备和容差均属于身份。D/Q 区别是具体输入，不能用重新抽样替换失败实例。

下表中的计算和字节数是**数学 oracle 目标**，不是已观测 SOLAR 输出。MAC/FLOP 采用 1 MAC = 2 FLOPs；外部流量示例均假设独立、完整物化的输出，并只统计注明的输入／输出。

| ID | 程序与输入 | D 实例 | Q 实例 | 必须检查的结果与阶段边界 |
| --- | --- | --- | --- | --- |
| F01 | `A @ B`；fp32 | A=(3,5)，B=(5,4) | A=(7,11)，B=(11,5) | D：60 MAC、120 FLOPs、188 B 外部 I/O；Q：385 MAC、770 FLOPs、668 B。两路径语义相同；资源分类另按 profile 核对 |
| F02 | `(x + 1).sum(-1)`；fp32 | x=(3,5) | x=(7,11) | 非 MAC 的逐元素／归约工作不得全部消失；归约维度、输出 shape 和对应资源正确；逐算子与全图公式用 M01 区分 |
| F03 | `(A @ B) @ C`；fp32，无 effects | 维度链 3→5→4→2 | 维度链 5→7→3→4 | 阶段 1–3 不改变结合顺序；分别报告 dense 计量和容量证据。容量测试用 M03 的显式情景，不冒充真实设备 |
| F04 | `(x[:a].sum(), x[b:c].sum())`；fp32 | x=(128)，a=64，b=32，c=96 | x=(192)，a=96，b=64，c=160 | D 唯一输入 96 元素／384 B，Q 为 160 元素／640 B；各有两个 fp32 标量输出共 8 B。检查 view 到底层输入的映射 |
| F05 | `x.float() + mask.float()`；x=bf16、mask=bool | 两输入均 (4,8) | 两输入均 (3,7) | 外部字节分别 224 B、147 B，输出 fp32；转换工作仍计入对应资源，不能全图套 bf16 字节宽度 |
| F06 | `tril(x, diagonal=0) @ w`；fp32 | x=(4,4)，w=(4,3) | x=(5,7)，w=(7,2) | 已有操作若可表达则回放，否则明确拒绝。阶段 1–3 保留 dense contraction 48／70 MAC；阶段 4 才可在支持条件下另报 30／30 MAC，不能提前折减 |
| F07 | `x.index_select(0, idx)`；x=fp32、idx=int64 | x=(32,4)，idx=[0,7,7,31] | x=(48,3)，idx=[47,0,12,12,1] | idx 是程序输入，不把 trace 时的值当静态索引证明。两例 idx 均显式保留（输入位置 1），x 按既定 patterns 变化；索引字节不可遗漏，未知区域不得标为精确并集 |
| F08 | `x[:a].add_(1); return x[b:c]`；fp32，可变输入 | x=(16)，a=8，b=4，c=12 | x=(24)，a=12，b=6，c=18 | 验证输入修改及 output/input alias；不能按普通纯读取消除边界。本族显式设 `verify_gradients=False`，因为测试输入原地修改；不由它宣称梯度支持。其他策略不变 |

F08 的特殊策略必须进入请求与基线身份，不修改其他族或生产默认策略。F07 的保留索引策略同样绑定实例。有限 mask 和异常值规则不得从 F06 泛化到其他程序。

已有测试可作为实现入口，但不声称与新样本一一等价：

- [两路径 MatMul](../../tests/solar/test_ir_backends.py)：F01。
- [主流程与输入／输出绑定](../../tests/solar/test_pipeline_integration.py)：F02、F04、F08。
- [native／ATen 能力与 effects](../../tests/solar/test_extended_native_v6.py)：F05–F08 的已支持语义。

## 3. G 组：区域并集的独立 oracle

G 组用小尺寸整数坐标枚举“实际访问的底层元素集合”，与生产几何代码分开实现；不能调用待测 region resolver 或 union helper 得到期望值。前三例 base 长度 128、fp32，均只比较输入读取。

| ID | 场景 | 期望 |
| --- | --- | --- |
| G01 | 同一 base 的 `[0:64]` 读取两次 | 64 元素／256 B |
| G02 | 同一 base 的 `[0:64]`、`[32:96]` | 96 元素／384 B |
| G03 | 同一 base 的 `[0:32]`、`[64:96]` | 64 元素／256 B，不取单次 max，也不取包围区间 96 |
| G04 | base=(8,8)，经 transpose 后取前 2 行，再加原张量前 2 行 | 两个底层条带并集 28 元素；坐标必须映射回同一 base |
| G05 | base=(8,8) 沿第 0 维 split 为 4 份，只消费第 1 和第 3 份 | 32 元素；保留不同 output slot 身份 |
| G06 | 两个独立 base，shape 都是 (64)，各读前 32 | 共 64 元素，不能合并；另加“显式共享存储但当前合同无法证明”的拒绝／保守分支 |
| G07 | 动态 tensor 索引；重复和不重复索引形状相同 | 不可从 shape 断言精确集合；保留索引读取并标明估计范围 |
| G08 | base=(128)：`[-16:-4]`、`[20:20]`、`[1:12:2]` 分别单独计量 | 数学集合分别为 12、0、6 元素；前两例归一化后精确，首批未支持的步长例明确保守回退／拒绝，不伪称精确 |
| G09 | base=(128) 的已归一化 bounds 声称 `[0:129]`；`[0:32]` 却声称 64 元素；同一 base 同时声称 shape=(128)/(64)；测试预算只容许 2 个区域却给出 `[0:8]`、`[16:24]`、`[32:40]` | 分别保留原因；前述合同损坏拒绝，预算不足时明确保守处理。Python slice 本身的合法截断不等于坏元数据；任何回退都不得超过可证明的必要读取量 |
| G10 | 读取间发生 mutation／atomic，或 view 需要 copy／要求连续输出 | 不跨 effect 消除读写或初始化；没有证明的 copy 不当成透明 view；别名语义与布局责任保持可观察 |

G09 中“合法但未知”与“合同损坏”必须区分；一个全图仍可产生保守下界，不意味着该局部区域精确，报告必须记录精确／保守／不可用的来源。

## 4. M 组：公式、复用与探索验收

本组是合成计量／合同输入，不是硬件测量。时间单位固定为秒，工作量及字节采用明确单位，测试 profile 仅用于探索。

| ID | 固定设计 | 期望 |
| --- | --- | --- |
| M01 | 两个串行算子，计算／访存时间分别为 (8,2)、(2,8)，不消除任何流量 | unfused=16；允许全图理想重叠的资源下界=10。不得把两者都算成 10 |
| M02 | 同一资源两个模式，工作量／速率分别 100/10、60/20；独立资源耗时 9；DRAM 耗时 12 | 共用资源=13，计算项=max(13,9)=13，全图下界=13 |
| M03 | F03-D 的相同合法链、mapping 域和字节宽度，对有限容量 64 B 与 4096 B 分别取曲线点 | 必要流量在容量增加时不变或下降；缺容量点／覆盖不全时 cache-aware unavailable；需真实 mapper 的部分单列，fixture 结果不充当工具验证 |
| M04 | F01/F05：一次完整流水线，一次使用同一验证工件重算 | 工作量、流量、时间与资格一致；证明重用路径没有执行 reference 或重复取图，而不是仅比较耗时 |
| M05 | 分别改变源码、IR、shape、dtype、effects、验证策略、执行身份、规则版本、profile 资源模型、容量、mapper 身份／预算，或篡改工件 | 逐类按任务 S2-01 失效表拒绝或重算；只有名义速率变化可在语义不变的前提下复用固有工作量 |
| M06 | 理想全图：工作量 120 ops、流量 80 B，目标 2 s | 必要速率 60 ops/s、40 B/s；反代正向理想模型为 2 s；不表示真实机器保证达标 |
| M07 | 同一资源两模式：100/10 + 60/20=13 s，目标 10 s；两模式只能按共同倍数扩展 | 所需资源倍数 1.3，不分别用 max(10,3) 得到 1；unfused 求和约束需另核对，不能冒用全图结果 |
| M08 | 目标时间为 0、负数、NaN、Infinity；资源或带宽为非正数；缺资源模式 | 明确拒绝；不默认为 0 时间、不返回成功的无穷大需求 |
| M09 | 固定 M06 的工作量与流量，基础吞吐 60 ops/s、带宽 40 B/s；两者倍率各为 {1,2}，容量不变，采用相同 ideal fused 模型 | 按 (计算倍率,带宽倍率)=(1,1)/(1,2)/(2,1)/(2,2)，时间为 2/2/2/1 s；无遗漏／重复，单项改善不使下界变差；一般报告中的并列最优按稳定规则输出 |
| M10 | 改变容量、扫描中断、部分失败、预算耗尽、恢复时工件漂移，或给假想配置附旧正式 audit | 逐点保留完整状态；恢复核对身份，失效项不跳过；假想配置始终无正式资格，不挑成功点改分母 |

## 6. 每次验收必须交付的记录

每次运行生成独立目录，至少包含样本 ID／角色／路径、源码和输入摘要、验证策略、环境身份、各阶段状态及原因、semantic replay 结果、工作量与字节计数、视图假设、工具证据身份、正式资格，以及相对 `BASE-01` 的逐项差异。具体 JSON schema 由 S2-01 定义，不在文档中预注册版本。

报告分别列出计划总数、实际尝试数、语义通过数、计量可用数、完整 cache-aware 数、正式资格数。超时、缺工具和不支持均留在原分母；CPU fixture、真实 mapper 和 GPU 证据单列。涉及性能收益时另列配对测量、重复次数和不确定性，本轮样本清单不设虚构的加速门槛。
