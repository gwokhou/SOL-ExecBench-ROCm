# E2 后继预检执行台账

日期为 2026-11-18。预检使用 E0 开发实例 `d0` 和已冻结的 P0 对照。沿用 `622c6ba3` 的执行源码、ROCm 镜像和 RX 9060 XT 原生所有权，另行记录预检脚本的哈希。预检的留出状态为未生成，评分适用范围为研究预检。

原活动在 [11 月 8 日台账](solar-e2-execution-2026-11-08.md) 保持 `INCOMPLETE`。本次证据位于 `data/outputs/solar-e2-preflight-20261118/`。开发集会话和中断夹具均在该新目录内单列。

## 临时空间和中断验证

固定镜像内为评测会话设置独立 256 MiB `tmpfs`。净化后环境仍用会话目录作 HOME，目录里的 `.cache`、`.tmp` 指向该临时盘。每次建立新的 MIOpen 用户数据库目录。采样记录临时盘已分配字节，结束时记录缓存文件逻辑尺寸及清理后的占用。另设 128 MiB 容器 `/tmp`，作为容器级系统临时空间。

无 GPU 设备容器写入 268,435,456 字节后，下一笔写入收到真实 `ENOSPC`。清理使该盘占用回到 0。首次 CPU 尝试沿用了 GPU 的时钟锁配置，在进入评测前失败，原日志保存在 `attempt-01-cpu-clock-contract/`。复跑只把 CPU 夹具的时钟配置关掉。

在两次实际 CPU 评测的第 3 次捕获后分别向本会话进程组发送信号。`SIGTERM` 后保留 3 份可核验原始工件，退出码为 −15。`SIGKILL` 后仍有 3 次捕获的进度记录，匿名工件随进程关闭，退出码为 −9。两次的最终裁判判定及之后可能发生的调用均为未知。已完成捕获在服务进程内写入无目录项文件，关闭私有连接时再公开。此预检验证的是可信开发候选下的有界留证和退出行为。后继确认前仍需核验匿名描述符访问边界及整容器强制退出情形。

GPU 测量后，单独记录采集限额退出分支的修订身份，并用无设备容器复核。在第 4 次捕获前缩小夹具限额，触发 `pilot_capture_quota_exhausted`，此前 3 份原始工件和停止原因均保留。该补充验证的源码摘要不同于 GPU 测量，两个身份分别存档。每会话匿名采集的常规上限为 1 GiB。

## 配对缓存条件和测量口径

每一侧从空的会话级编译缓存和新的评测／参考进程开始，缓存和数据库在该侧结束后清理。每个成本会话内依旧执行 3 个 trial，每个 trial 都有 10 次预热和 50 次计时调用。两侧都能从各自预热和前序调用积累缓存。这里的冷启动限定在会话级磁盘缓存及进程生命周期，宿主页缓存、驱动全局状态保持实际运行状态。预检执行一次 `r0`，顺序为原检查加等量留证、再加在线 oracle。每侧以独立 nonce 派生输入，匹配任务、shape、family、候选和调用结构。

会话墙钟含原评测、真实调用采集和落盘，以及诊断侧的在线 oracle。基线侧的离线 oracle 在无 GPU 设备的容器中单列耗时和落盘。NPZ 和日志以逻辑字节计量，另记文件实际分配字节及临时盘采样峰值。配对耗时反映这次预检的完整流程，单次运行仍含次序与进程启动波动。

预检正确性选 GEMM `w1/G0`、sum `w2/R0`、LayerNorm `w1/L3`，覆盖大输出或大输入。按 E0 成本形状 `w0` 选择 `G0`、`R0`、`L3` 各一对。`L3` 使用变化的整行输入与 affine 参数，是本次高成本探针，因为区间 oracle 需要对整张输出求值，重复行复用机会少。

## GPU 观测结果

单位为秒和 MiB。保留量为在线评测结束后会话目录的逻辑字节，离线诊断另列。

| 任务与样本 | 正确性墙钟 / 保留量 | 成本原检查侧墙钟 / 保留量 | 成本在线诊断侧墙钟 / 保留量 | 成本配对墙钟差 |
| --- | ---: | ---: | ---: | ---: |
| GEMM `G0` | 9.81 / 17.82 | 8.68 / 16.42 | 13.94 / 29.26 | +5.26 |
| sum `R0` | 8.20 / 11.10 | 6.84 / 6.66 | 7.71 / 7.25 | +0.87 |
| LayerNorm `L3` | 21.93 / 46.16 | 10.23 / 43.06 | 160.86 / 418.97 | +150.63 |

9 个会话的原 gate 均为 `PASSED`。每个正确性会话有 11 次候选观测与 12 次参考调用。每个成本会话有 190 次候选观测与 371 次参考调用。LayerNorm 的 `w1/L3` 和 `w0/L3` 在线诊断分别记录 11 次和 190 次更强数值保证失败，原 gate 仍按其冻结容差判定通过。全部观测工件保留原判定与独立诊断分类。

会话临时盘采样最高 119.15 MiB，发生在 GEMM。GEMM 的 COMGR 文件实际进入 tmpfs，所有会话结束后该盘均归零。9 个会话共用时 248.18 秒，在线会话目录合计 625,676,390 逻辑字节（596.69 MiB）。GPU 主所有权持续 253 秒，交还时为 AUTO，设备进程为 0，L1/L2 均释放。

LayerNorm 诊断侧记录的 oracle 墙钟为 90.38 秒，证据编码为 63.07 秒。两侧会话墙钟相差 150.63 秒，反映整条路径的差异。最重单侧在原 300 秒会话上限内完成。一次配对尚不足以估计重复波动或给全分母建立资源上界。会话墙钟的截止点在逐文件事后核验之前，累计占用仍应以实际所有权窗口计。

## 离线诊断及完整预算

无设备容器逐组重放原检查侧的 190 份现有工件。GEMM 用时 7.75 秒并新增 28.71 MiB，sum 为 2.05 秒和 6.69 MiB，LayerNorm 为 153.79 秒和 418.26 MiB。三组均关闭 GPU 可见性与设备挂载，全部 570 份诊断工件完成。

最重的单组 LayerNorm L3 连同离线诊断合计约 880.28 MiB。若按本组观测量计算 E0 的六个 L3 配对，单这一格约 5.16 GiB。这个情景假定两种候选都走完整 190 次调用，字节量以本次 P0 样本计。

[完整预算核算](solar-e2-successor-budget-2026-11-18.md) 已逐行对齐 1,296 个正确性和 144 个成本会话。基准为 17.14 GiB、持有 GPU 约 4.15 小时，压力情景为 21.06 GiB、6.30 小时。即使将离线放到 GPU 交还后，证据预算仍未确认，确认活动继续留在预登记前。按核算中的开发槽位清单补测，包括近峰值的停止和留证。
