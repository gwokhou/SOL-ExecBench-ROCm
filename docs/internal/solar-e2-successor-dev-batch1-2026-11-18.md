# E2 后继实验第一批开发集补测

目标是把裁判辨错和成本实验完整跑通。本批为[预算核算](solar-e2-successor-budget-2026-11-18.md)中的第一批开发测量。基础评测源码固定为 `622c6ba3`，沿用 RX 9060 XT、固定 ROCm 镜像和原生 GPU 所有权。测量槽和运行脚本另有 SHA 绑定。本批范围为 `d0/d1`，留出密钥和实例尚未生成。

## 在线部分

断言第一批清单恰好包含 26 个正确性会话和 18 个成本会话，对应 9 组 LayerNorm 配对。实际启动前列入全部 44 行，保留原 gate 的判定和停止原因。两侧均以新的进程和空的会话级磁盘缓存启动。超时和意外的运行时／参考故障停止队列，保留未到达项。补测独立的 GPU 墙钟预算为 40 分钟，输出规划限额 8 GiB，调度串行。

在线证据位于 `data/outputs/solar-e2-dev-batch1-20261118/`。`gpu-launch.json` 绑定镜像、设备、槽表和代码，`gpu/ledger.json` 记录当前实测。每会话新增 cgroup 内存、设备 VRAM、磁盘可用块变化和匿名采集进度采样。整个容器的 cgroup 内存高水位与会话采样峰值分开。磁盘可用块变化是该文件系统的总量观测，同盘活动可能影响它，分项另有具名文件实际分配量和匿名采集字节。

在线 44 项全部结束，GPU 时钟恢复 AUTO，设备进程清空，L1/L2 锁释放。26 个正确性会话中，GEMM 六槽为 5 通过、1 数值拒绝，sum 六槽为 5 通过、1 数值拒绝，LayerNorm 十四槽为 6 通过、8 数值拒绝。LayerNorm `w0/L0/d0/P3` 在首个检查拒绝，`w0/L1/d0/P3` 在第十个检查拒绝。两次拒绝的观测均记录候选通过更强诊断、参考和 oracle 在原容差上分歧。预算中的首调用退出仅是敏感性假设，实际 L1 行需按观测重新校准。

L0–L2 的 12 个在线成本会话已完成。L0、L1 的 P3 在两侧均走短路径，保留为数值拒绝。包括 L2/P3 在内的四个完整在线诊断会话均有 190 份候选观测，用时约 18–19 秒。L3 在线阶段仍以 `gpu/ledger.json` 的实测为准。

L3/P0 的反序配对中，在线诊断侧 190 次调用用时 163.23 秒，具名文件实际分配 419.25 MiB，原检查侧 190 次调用用时 10.33 秒。L3/P3 的两组重复同样走满，诊断侧约 163 秒，原检查侧约 10.5 秒。在线各会话合计分配 1,885,949,952 字节，容器内存采样峰值 3,775,897,600 字节，设备 VRAM 采样峰值 956,841,984 字节。分母和全部停止原因见在线台账。

## 参考结果偏差复核

对全部 26 个正确性槽的 201 份原始工件校验 SHA 后，按原容差复核最小余量。以独立 oracle 的舍入值为中心，按同次调用实际测得的参考偏差逐元素求余量上下界。191 次严格为正，4 次严格为负，6 次跨零或贴近零。GEMM G2、sum R0 和 LayerNorm L3 的三个 P1 见证均有严格负余量。共有 7 次 reference/oracle 分歧。上文 L0/L1 的拒绝点均跨零，仍列为不确定，不能计入已确认误拒。

开发复核录于 `reference-margin-development-review.json`，其源码为 e2_reference_margin.py（`scripts/internal/solar/e2_reference_margin.py`，已归档于 tag `v0.1`）。该方法只约束观察到的有限参考偏差；进入后继确认前还需登记适用条件和分类规则。

## 留证预算的实现复核

预算检查（`scripts/internal/solar/e2_evidence_budget.py`，已归档于 tag `v0.1`）在前一写入者排水后清点逻辑字节与实际分配块，显式保留下一写入者上限和收尾空间。关闭的在线子树实测 1,878,097,414 逻辑字节、1,886,560,256 分配字节，后者包含目录和台账。记录见 `evidence-admission-fixture.json`。

匿名采集（`scripts/internal/solar/e2_archive_spool.py`，已归档于 tag `v0.1`）在写入前按文件系统分配单位预留块，拒绝超过上限的下一份包，再用已写文件的实际分配块复核。取 L3 反序配对最后一份原始包，在 CPU 夹具中写入、发布并复验 SHA，保留 2,308,327 逻辑字节，匿名文件预留 2,310,144 字节。记录见 `archive-spool-fixture.json`。这两项组件验证用于后继执行器集成。正式活动启动仍依赖全分母预算和实际中断验证。

后继采集进程（`scripts/internal/solar/e2_successor_capture.py`，已归档于 tag `v0.1`）持有候选进程的 Linux PID 文件描述符，在其退出后发布归档和 nonce。独立分支的暂存评测进程在私有连接关闭后退出，由既有进程组管理器排水。参考进程启用 Linux nondumpable 属性。固定镜像、无设备容器验证了两个 `d0` 会话。GEMM G0/P0 通过并发布 11 个原始包，G2/P1 被原数值检查拒绝并发布 1 个原始包。源码与镜像身份见 `data/outputs/solar-e2-successor-cpu-20261118/launch.json`，判定见同目录 `publication-fixture.json`。

独立输入重放（`scripts/internal/solar/e2_input_replay.py`，已归档于 tag `v0.1`）使用发布的 nonce、冻结实例 seed、实际 workload 身份和调用坐标复验 12/12 个量化输入，并核对原始包、参考输出、候选输出的摘要。错误 seed 在两个会话上均被拒绝，结果录于 `input-replay.json`。这验证了正常收尾与证据重放接缝，近峰值时的同身份中断还待验证。

## 第一批核验终态与后续补测

GPU 交还后，9 个无设备离线回放全部完成。每次调用原子提交诊断包及收据，全部 1,332 份均通过校验。会话墙钟累计 540.21 秒，新增实际分配 1,484,587,008 字节，最高容器内存峰值 844,312,576 字节。三次 L3 离线回放各处理 190 份工件，实际为 158.48–159.18 秒。9 个成本配对中 7 组两侧均走满 190 次调用，其余 2 组两侧均在首个调用被原数值检查拒绝。逐项对账见 `measurement-summary.json` 和 `deferred/ledger.json`。

近峰值中断夹具单独登记，用完整 LayerNorm L3 成本形状区分可验证的前缀、未完成写入和最终判定未知。
原格式的 SIGTERM 探针在第 189 份采集后停止，189 份原始工件全部通过校验，最终裁判判定保留为未知。临时盘清零、GPU 正常交还，从最后采集记录到时钟恢复收据约 2 秒，收据精度为秒。证据见 `data/outputs/solar-e2-dev-late-fault-20261118/fault-summary.json`。
同节点 SIGKILL 留下第 189 份采集的进度记录，进程关闭时匿名原始包全部丢失，最终裁判判定仍为未知。设备、时钟和两级锁均正常交还。
采集限额探针在第 189 份之后、下一份写入前停止。189 份原始包全部通过校验，最终裁判判定仍为未知，GPU 正常交还。剩余中断验证针对离线原子写入。
离线 SIGTERM 通过，188 份已提交工件经核验，另有 1 份未提交。离线 SIGKILL 首次夹具失败：容器内 PID 1 继续执行，`call-188` 由半份前缀和完整归档拼接，导致该工件 SHA 核验失败。失败目录原样保留。只重跑这一分支，沿用原输入和源码，在新目录使用容器 init 管理被测子进程。紧凑格式验证的续接在新执行目录等待修复收据。
修正后的 SIGKILL 复验退出码为 137。188 份已提交工件与 SIGTERM 路径的源和派生摘要一致，另有 1 份未提交写入与已验证半份前缀逐字节相同。该写入与最终判定保留为未知，详见 `data/outputs/solar-e2-late-offline-kill-r2-20261118/verification.json`。紧凑格式续接已启动。

第二批 GEMM／sum 的 16 组配对已与冻结会话逐项对账，入口在 `data/outputs/solar-e2-dev-batch2-20261118/`。
串行接续状态和重算工具位于 `data/outputs/solar-e2-dev-calibration-20261118/`。第一批对账完成后，先进行只读开发工件的无损编码复核，再启动第二批。双批次测量收尾后进行全分母重算。

本页的验收以实际终态回填为准。原 E2 继续保留 1,440 行完整分母和预算停止记录。本批未启动 C2/C3 或正式评分发布工作。
