# 裁判验证后继活动执行规格草案

状态为草案。原 E2 的停止记录、证据和留出承诺按[原执行台账](solar-e2-execution-2026-11-08.md)独立保留。当前后继活动只使用开发实例，正式执行身份和留出承诺尚未建立。

## 固定分母

沿用 [E0](solar-m0-judge-preregistration-2026-11-07.md) 的三类任务、shape、输入族、候选策略、三次独立进程重复和判据。正确性保留 432 个候选—case 单元与 1,296 个会话；成本保留 24 个块、72 个两侧配对与 144 个在线会话。每个原检查侧随后离线重放实际工件，共 72 个预先声明的离线会话。成本原顺序按重复反转。调用计数使用获批的 [E0 勘误](solar-e0-cost-count-erratum-2026-11-08.md)，预热、检查和四组策略继续按冻结定义执行。

## 执行身份和开启条件

正式确认前冻结执行树、镜像、设备、依赖、候选／输入生成器／oracle、采集与报告代码、两条阶段命令、资源限额和完整行序。准入证据包括已验证的预算预测、相同采集身份下的开发成本及中断证据、新执行身份的 B2 资格和独立收据复核。验证原始输入和输出身份的程序使用固定执行源与镜像。开启时先写入完整 roster，再把新随机留出承诺绑定到 freeze 和 roster。密钥由控制器持有，候选之外维护；实际留出只以固定算法派生一次。

冻结校验（`scripts/internal/solar/e2_successor_freeze.py`，已归档于 tag `v0.1`）读取固定行序、B2、两阶段预算、中断证据、候选工件和采集源码摘要。已在现有 B2、预算和修正后的中断收据上验证。先前的紧凑格式开发集测量已完成 8 个在线会话、4 个离线回放、1,520 份实际输入核对。加入累计 oracle CPU 计量和正式入口的采集版本，有独立开发冻结和复验。正式准入使用收据与采集源码匹配的版本。

当前已实现完整 roster 和逐次收据（`scripts/internal/solar/e2_successor_ledger.py`，已归档于 tag `v0.1`）、在线／离线阶段控制（`scripts/internal/solar/e2_successor_campaign.py`，已归档于 tag `v0.1`）和在线评测适配（`scripts/internal/solar/e2_successor_runner.py`，已归档于 tag `v0.1`）。固定镜像中运行了两条开发集 CPU 评测，正常对照通过，语义错误被原判据拒绝，12 份输入可独立重放。两条均有 oracle CPU 计量和临时盘归零收据。

运行入口（`scripts/internal/solar/e2_successor_entry.py`，已归档于 tag `v0.1`）须在固定镜像中通过 `python -B -P -m scripts.internal.solar.e2_successor_entry` 调用。在线阶段先核验冻结、原生 GPU 所有权、设备和空临时盘。其后只有显式授权开启才登记一次性承诺。离线阶段先核验同一所有者按时恢复时钟并交还设备，再在无设备容器中逐会话重放。固定镜像下的离线入口已在一条开发会话上复验 190 份诊断，归档与前一版一致。主 GPU 阶段在 6 小时截止前预留 60 秒排水和关闭。

准备工具（`scripts/internal/solar/e2_successor_prepare.py`，已归档于 tag `v0.1`）在新目录逐文件复制并核验研究源码与准入收据。它核对原 E0 和勘误的冻结摘要、B2 回执、压力预算和中断证据，再检查当次采集版本的四组成本配对及离线回放。实测超过相应压力预测时，需先重核预算。当前绑定清单的 11 份前置工件已存在并完成相关校验，最后一份是本版开发复验的终态测量。准备工具只组装冻结件。

## 在线和离线

两个成本侧均使用新评测与参考进程和空的会话级缓存。256 MiB 专用临时盘承载会话级缓存，每会话结束清零。在线成本侧执行原评测、真实发起的调用采集，以及诊断侧固定的独立 oracle。候选退出后发布原始数据和输入 nonce。字节完全相同的输出允许复用存储，读端恢复同一 dtype、形状和内容。

原生 GPU 所有权覆盖全部在线会话及其退出收尾。在线结束后，实际设备空闲、时钟恢复 AUTO、L1/L2 释放的接收收据须绑定到在线阶段结果及 roster。无设备离线阶段仅重放原检查侧已经采集的工件，分别绑定原始归档和新增诊断包的 SHA，并验证实际输入和输出身份。离线墙钟、CPU oracle 开销及峰值单列。

## 资源和中断

沿用 6 小时累计 GPU 占用、12 小时累计 CPU oracle 时间及 20 GiB 证据上限。逐正确性会话 120 秒，逐成本会话 300 秒，单次 oracle 120 秒。按照[完整预算台账](solar-e2-successor-budget-2026-11-18.md)为下一写入和收尾预留空间。离线同时只分配一个待提交归档，上限 48 MiB；已提交归档按实际占用计入下一会话准入。阶段失败时保存首次具体原因、已知身份和未覆盖分母，缺少有效终态收据的执行标为中断，判定和无法计量的资源用量保留为未知。

新版oracle CPU 计量（`scripts/internal/solar/e2_oracle_budget.py`，已归档于 tag `v0.1`）保留成功和失败调用的消耗，耗尽时停止本次诊断。CPU 夹具在实际工件上验证了正常重放和极小额度时的停止。10 微秒夹具因内核计时器及解释器派发实际消耗约 1.73 毫秒，诊断包没有提交。正式运行仍需核验活动级预算和临界额度预留，报告采用实际消耗。

## 验收和报告

实验完成要求在线和离线终态、全部分母、原始证据和冻结身份可复核，同时明确所有失败、未知和不满足条件的配对。裁判是否达标按 E0 独立判定，报告 P1 必检锚点、已确认合法对照、P2 强诊断结果、复现分歧、参考与 oracle 分歧和成本。原 gate 数值拒绝也作为完成的实验观测保留。离线分析不得用于替换原评测判定。正式实验报告与评分系统分离。

独立数值标签（`scripts/internal/solar/e2_successor_labels.py`，已归档于 tag `v0.1`）从已核对哈希的实际数组、原容差和认证 oracle 计算严格余量，同时保留原 gate 判定。五份开发工件复核中，三类任务的 P1 锚点均确认违例，LayerNorm L0/L1 的两例参考分歧仍为不确定。针对漏检的测试覆盖了原 gate 通过、独立标签确认违例的情形。

结果报告器（`scripts/internal/solar/e2_successor_report.py`，已归档于 tag `v0.1`）从同一执行台账重建 432 个逻辑单元的三次重复，分开记录原裁判 call 判定、复算判定和独立标签。缺失与中断保留原状态，不参与确认分母。它核对24 个成本块与 72 个配对（`scripts/internal/solar/e2_successor_cost_report.py`，已归档于 tag `v0.1`），区分双侧完整调用和提前退出，并独立记录离线成本。开发预演读入 26 个已完成正确性会话、25 个已观察成本配对和 25 个离线回放，识别 23 个双侧完整配对。其余条目保留，报告不作正式结论。

独立证据核验（`scripts/internal/solar/e2_successor_audit.py`，已归档于 tag `v0.1`）在无设备端对账全部 1,440 个在线会话和 72 个离线会话。它核对留出承诺先于在线启动、按已封存的种子复现输入身份、验原始输入与两侧输出的摘要，并核对每个已提交的离线诊断与原始调用的对应关系。中断会话的未知判定、无法复演的输入和未到达行保留在台账中。
