## 预算停止原因与资源收尾

原环境净化将 `HOME` 指向每个会话暂存目录，且不传递 `XDG_CACHE_HOME`。
实际现场显示每个会话形成独立 `.cache/comgr/`，其中一个约61.56 MB的缓存文件反复留存。
停止后保留文件约19.978 GiB：缓存20,121,110,112字节（约18.74 GiB，93.8%），
实际观测NPZ为1,312,688,096字节（约1.22 GiB）。证据监视器按会话目录总字节数计费，
缓存因此耗尽20 GiB限额。监视器未保存瞬时峰值；排水清理临时文件后的保留量不能反推峰值，
也不能用它否认已记录的预算触发。全部缓存和失败现场继续保留。

本次E2原生所有权收据合计2145秒；从冻结到末次交还约2157.525秒，均未提高6小时上限。
已完成调用记录的oracle CPU用时219.227秒；中断会话未完成留证，故不称为完整活动CPU总量。
收尾独立核验：时钟AUTO、GPU进程0、相关镜像容器0、L1/L2无持锁记录、admission ready且owner=null。

## 研究观测接入

E1 只有开发集 CPU 执行器，生产路径没有实际候选输出与分项成本留证。因此新增默认关闭的
正确性观察回调，以及参考 client/service 类型注入与关闭接口；默认评测路径仍执行原检查。
研究执行器在独立暂存目录对原 driver 模板作精确、次数校验的观测插入，保留所有静态、
运行时完整性、私有管道认证、逐计时调用重验和时钟检查。

候选的实际输出在原检查后交给私有参考 worker，与该次真实输入/参考输出对应；不重跑候选。
正确性原数值结论、CPU 原判据重算、独立更强诊断分列。worker 不回传 oracle、角色或种子；
私有会话配置在 READY 前删除，公开 config 的 seed 为中性值，derived UUID 使用不含角色的随机标识。
调用级私有 nonce 和实际 derived UUID 留在关闭后的证据中；h0 密钥只在活动控制器内存中使用，
先写 commitment，所有候选进程关闭后才保存用于复验的密钥。

两个成本模式均捕获真实输出。原检查模式的 oracle 在会话结束后离线执行，单列 CPU 预算；
诊断模式的 oracle 在私有 worker 中同步执行，耗时进入会话墙钟。记录准备、reference/IPC、
原比较检查、静态审查、完整性检查、oracle、证据编码、总墙钟及峰值 RSS。分项存在包含关系，
不得直接相加或把差额全称作 oracle；计时结果均无正式性能权威。
