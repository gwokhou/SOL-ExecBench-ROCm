# SOLAR S5：有预算的收缩顺序搜索

进度以 [HANDSOFF](../../HANDSOFF.md#solar-evolution) 为准，验收规格见 [S5-01–03](solar-stages1-5-implementation.md#3-s5收缩顺序搜索p2)。当前仅实现和验证 CPU 算法、语义回放及工具 fixture；没有 GPU 性能或发布资格结论。

## 搜索域和原始参考

首个支持域为 2–12 个固定形状、同一浮点 dtype 的二维矩阵组成的纯收缩链，每个原始输入恰好使用一次，只有一个矩阵输出。支持原生 `mm`／二维 `matmul` 及具有相同矩阵索引关系的二输入 einsum。保留输入顺序，仅枚举二叉结合树。广播、批量／高阶收缩、转置或 view、动态维度、effects、共享中间结果、重复输入和图外其他操作显式拒绝，不能借数值样本推断它们可重结合。

每个候选携带源输入索引、维度、dtype、后序结合树、精确 MAC、各中间矩阵大小以及输入与输出的物化元素数。树中非负数是有序叶节点，`-1` 是二输入矩阵乘法。总分母由 Catalan 数精确计算；生成器只展开候选预算允许的前缀。原图始终排第一，同价时按此顺序稳定选择。独立 oracle 使用逐次合并相邻矩阵的调度枚举，核对完整小链的树集合、MAC 和中间大小。

调用者必须重新提供原始 `ConversionRequest`。它的参考摘要、名称、路径、trace seed 和完整验证策略必须与源工件一致。候选函数只用于提取；其 IR 对照原始参考函数执行既有随机／零／边界模式、原种子、数值容差和梯度验证。不会把候选自身或已转换的 IR 当作数值 oracle，也不放宽策略。搜索要求源策略启用梯度；原本关闭梯度的源不能被悄悄升级或接纳。

浮点重结合不保证满足该策略。严格零误差上限的标量矩阵反例中，原始结合通过，而右结合因数值差异失败；失败图和错误记录保留，未产生成功验证清单。每条 IR 路径独立搜索，不能跨路径选择较低成本掩盖差异。

## 计价和证据

原始已验证图先通过阶段 2 生成单独的 `baseline/`，不覆盖已有源工件。每个通过验证的候选重新分类资源、分析容量并生成三视图。比较使用相同 profile、精度、mapper 身份与约束。没有完整容量证明时，cache-aware 仍不可用。所有搜索投影标为 hypothetical，不继承 SOL Score 或发布资格。

选择 `computation="restricted"` 必须显式提供阶段 4 的 `projection.restricted`。纯矩阵链没有额外结构零时，有限数值域情景保留原图工作；默认 IEEE 情景不可用，不能以 dense 时间顶替受限估计。原始与候选的各视图、约束和资格分别留存。

F03-D 原始左结合为 84 MAC、右结合 70 MAC；F03-Q 分别为 165／224 MAC。测试用明确的计算受限假想 profile 验证选择最低模型成本；原始带宽受限 profile 的 ideal-fused 时间可能相同，此时保留原始结合。四矩阵测试的五棵树分别为 76、80、84、102、110 MAC，必须逐个验证后再选择。以上均为模型结果，不是 GPU 加速数据。

## 预算、恢复和公共入口

默认最多 64 个候选、总预算 300 秒、单候选 30 秒。执行前检查候选每次调用的 MAC 和输入／全部算子输出物化量，硬上限为 1000 万 MAC、100 万元素；计数自身不枚举张量元素，超大但全空的形状可廉价接受。该模型预算针对受支持的张量程序；原始 Python input factory 仍由调用者负责提供与固定源相符的输入。隔离 worker 另外施加总进程超时、输出上限和进程组清理。

每个候选有 `analyzed`、`view_unavailable`、`verification_failed`、`failed`、`work_budget_exhausted`、`timeout` 或 `not_run` 状态。未展开的 Catalan 尾部也计入未探索分母。只有完整域全部完成数值判定、且通过者的选定视图均可用时，才报告该已验证域内的最小值；其他结果仅为已知最佳候选。失败、超时或缺证明不记作零成本。

公共 API 是 `solar.order.search_contractions(conversion, request)`。`OrderSearchRequest` 包含原有 `ReuseJob`、视图、情景、预算及可选的前次记录 pin。每次输出新目录；成功／视图不可用／明确数值失败／工作预算拒绝的完整记录可在同一身份下复用，超时或其他失败在新目录重试，原目录保留。规则、路径、源、profile、数值约束、预算或执行入口漂移均拒绝恢复。

CLI 为 `uv run sol-execbench --format json solar search-orders REQUEST.json`。外层请求使用 canonical `solar_order` schema，包含 `search` 和 `oracle`：后者指定本地 `.py` 文件的绝对路径、SHA-256、原参考名称及 trace seed。模块必须定义 `reference(*inputs)` 与 `input_factory(seed)`；模块摘要必须就是原已验证源的参考摘要。只有隔离 worker 会执行这份精确字节内容，其导入依赖由锁定环境提供。模块文件改变时先拒绝，不加载新代码。

`order-search.json` 记录完整计划身份、原始 baseline、每个候选状态、选中原因和分母。每个 `candidate.json` 绑定其完整目录，包括失败中间工件。读取／恢复检查当前 schema、目录清单、摘要、原参考验证、实际候选结合树、投影身份及计价；缺失或损坏不成为缓存成功。中断保留已完成记录和未运行状态；准备阶段若尚未构造有限计划便超时，明确报准备失败。
