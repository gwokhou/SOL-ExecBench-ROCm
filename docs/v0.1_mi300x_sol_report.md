## 2. 执行摘要（Executive Summary）

本次 `v0.1` 全量实测在 `MI300X` 真机上完成 **`34 × 3 = 102`** 组独立隔离计时（**Tier 1 `portable` `34/34` 通过**、**Tier 2 `vllm` `34/34` 通过、零 `unavailable`**、**Tier 3 `aiter` `30/34` 通过、覆盖 `7/8` Definition**），并在全 6 大原语族的 **15 组关键算子-层级组合** 上采集了硬件证实的 `rocprofv3` PMC 计数器。核心工程发现如下：

1. **FP8 Skinny GEMM 存在 2.05x–2.49x `vLLM` 默认分发退化（`DISPATCH_GAP`）**：
   - 在 `skinny_gemm_fp8`（`N=4096, K=7168, M=1..128`）上，Tier 2 (`vllm_fp8_scaled_mm`) 稳定卡在 `0.1025–0.1455 ms`（仅 **`6.9%–7.7%` Emp SOL**）；同卡 Tier 3 (`aiter_gemm_a8w8_bpreshuffle`) 仅需 `0.0497–0.0585 ms`（**`15.6%–17.4%` Emp SOL**），快 **2.05x–2.49x**。
   - `rocprofv3` 在 `M=16` 上测得两者真实 HBM 访存流量完全一致（十进制 `1 MB = 10^6 B`，与上文缓存容量二进制 `MiB` 区分：`vllm` `30.46 MB` / **`Amp = 1.03x`** vs `aiter` `30.46 MB` / **`Amp = 1.03x`**，仅 MFMA 指令数因分块不同呈 `114,688` vs `57,344`），用硅上硬件计数器直接排除“额外显存读写”假设，锁定 `vLLM` 退化根因为窄 `M` 矩阵缺少预重排与专属 tile 调度。
2. **DeepSeek 吸收态 MLA Paged Decode 长上下文汇编内核优势明显，短序列反被调度开销抵消**：
   - 在 `mla_paged_decode`（`HQ=16, DCKV=512, DKPE=64`）长序列 `S=32768` 上，Tier 3 (`aiter_mla_decode_fwd`，加载手写 gfx942 汇编内核 `mla_dec_stage1_bf16_a16w16_subQ16_mqa16.co`) 在 `B=16` 达到 **`51.0%` Emp SOL (`0.3151 ms`)**、`B=8` 达到 **`33.9%` Emp SOL (`0.2369 ms`)**，领先 Tier 2 `vllm_triton_mla_decode`（`0.4213 ms` / `0.4023 ms`）**1.34x–1.70x**；而在短上下文 `S=4096`（工作集仅 `~38 MB`）下，轻量级的 Tier 1 `triton_splitk_paged_mla`（`0.0726 / 0.0793 ms`）反而比 `vLLM` 与 `AITER`（`~0.15–0.16 ms`）快 **~2x**。
3. **GQA Paged Decode 与 Fused MoE 呈现显著分层加速（最高 3.10x）**：
   - `gqa_paged_decode`（`B=16, S=32768`）：`vllm_paged_attention_rocm`（`0.3757 ms`, **`76.1%` Emp SOL**）与 `aiter_pa_fwd_asm`（`0.3902 ms`, **`73.2%` Emp SOL**）较 `portable` Split-KV Triton（`1.2078 ms`）提速 **3.10x–3.21x**。
   - `fused_moe`（`E=64, top_k=6` BF16 / FP8）：`vLLM` 与 `AITER` 较 `portable` Triton 快 **1.33x–1.99x**；`rocprofv3` 在 `fused_moe_fp8_m32_e64_k6` 上证实 `portable` Triton 因将 FP8 权重/激活转回 BF16 执行计算，实测 HBM 访存达 `813.68 MB`（**`Amp = 2.02x`**、`1.57M` MFMA），而原生 FP8 路径的 `vLLM`（**`Amp = 1.02x`**、`410.67 MB`、`786K` MFMA）与 `AITER`（**`Amp = 1.01x`**、`408.20 MB`）消除了 2 倍流量放大。
4. **融合访存放大 `Amp` 与核函数启动延迟地板的物理张力（`SwiGLU+FP8` / `RMSNorm+RoPE`）**：
   - `rocprofv3` 精确测量出单趟融合与两步拼装的物理流量差异：在 `swiglu_fp8_quant_m1024_i4096` 上，单趟融合 `portable` Triton 实测 **`Amp = 1.00x`**（`21.04 MB` vs 理论必选 `20.98 MB`），而 `vLLM` / `AITER` 两步算子（`silu_and_mul` 写回 BF16 再由量化 kernel 重读，理论 `(4+2+2+1)/5 = 1.80x`）实测均为 **`Amp = 1.80x`**（`37.85 MB` / `37.82 MB`）；在 `fused_rmsnorm_rope_bf16_m1024_h32_d128` 上，`portable` 实测 **`Amp = 1.00x`**（`25.71 MB`），而 `vLLM`（`aten::add` + `fused_qk_norm_rope`）实测 **`Amp = 1.68x`**（`43.10 MB`，理论 `10/6 = 1.67x`）。
   - 同时因为 `M <= 128` 时理论 `t_sol_ms` 处于 **`4 ns – 0.6 ms`** 亚微秒到亚毫秒量级，远低于 MI300X 实测 `~32–47 µs` 的 HIP Kernel Launch 调度地板，因此在 `M=1024`（`~38–43 MB`）以内，`vLLM` 更低 launch 开销的 C++ HIP 算子仍快 `1.38x–1.44x`，完美解释了何时该优化融合 `Amp`（大 `M`）、何时该优先优化 Launch 开销（小 `M`）。
   - Tier 3 `aiter` 在 `fused_rmsnorm_rope` 上按契约诚信标记为 `unavailable:aiter_rmsnorm_rope_unsupported`：实测容器内 `aiter::rotary_embedding_fwd` 强制要求双路 Q+K 张量输入，与单分支独立原语定义不匹配（不伪造支持、不做无意义封装）。

## 3. 评测方法学：防失真隔离计时与双分母解析 Roofline

本仓彻底旁路 `Orojenesis` 重型离线搜索，所有评测指标由 [scripts/mvp_v1/](../scripts/mvp_v1/) 透明计算生成，关键护栏全部代码可审计：

1. **LLC 轮转冲刷 + 自适应无克隆输入环（[anti_distortion.py](../scripts/mvp_v1/anti_distortion.py#L186-L244)）**：
   - `LLCRotatingFlusher` 分配 `>= 2x` Infinity Cache 的缓冲区（MI300X 上达 **`512 MiB`**）并在每次热身/正式计时前原地读写失效缓存行，阻断跨轮次缓存热命中；
   - `_build_timing_pool` 对高带宽小工作集动态分配足量 `1 + warmup + rep` 个互不重叠的张量副本，确保原地修改算子在不引入计时内 `.clone()` 额外流量的前提下零相互污染；
   - 计时外完成全部输入输出张量物化检查、`float32` 转换下 FP8 `isfinite` 校验，以及逐 `Workload` 独立 `FlashInfer-Trace` `ToleranceSpec` 精度比对。
2. **Setup 阶段预打包零污染（[vendor_adapters.py](../scripts/mvp_v1/vendor_adapters.py)、[vendor_adapters_ext.py](../scripts/mvp_v1/vendor_adapters_ext.py)）**：
   - 所有权重转置（`w_t.t().contiguous()`）、`B-preshuffle`、`block_tables`、`seq_lens` 与 token 级 MLA CSR 展开表统一放在 `PreparedRunner` 初始化阶段生成，`start_ev .. end_ev` 窗口内只测纯计算/访存算子本身。
3. **双分母解析式 Roofline 定义（[analytical_roofline.py](../scripts/mvp_v1/analytical_roofline.py#L292-L488)）**：
   - **Spec Roofline (`t_sol_ms_spec`)**：分母取自硬件架构档案（`MI300X`: HBM `5.30 TB/s`、BF16 `1307.4 TFLOPS`、FP8 `2614.9 TFLOPS`）；
   - **Empirical Roofline (`t_sol_ms_empirical`)**：分母取自每次运行前现场测得的同卡启动微基准天花板（HBM Triad `~3.72–3.76 TB/s`、BF16 GEMM `~504–562 TFLOPS`、FP8 GEMM `~733–750 TFLOPS`），剥离硬件峰值不可达比例，精确衡量软件栈实际可回收优化空间。

## 5. `gfx942` 硬件计数器核准与 15 组硅上 `Amp` 归因

## 6. 复现命令与本地产物 SHA-256 证据清单

### 一键复现流程

```bash
# 1. 上云前无缓存 Python 3.12 语法与契约孪生校验
uv run python -m scripts.mvp_v1.cloud_preflight twin --target MI300X

# 2. 在含 vLLM + AITER 的 MI300X 容器中运行三层全量防失真采集
for tier in portable vllm aiter; do
  python3 -m scripts.mvp_v1.cloud_runner \
    --mode full --device cuda:0 --target-override MI300X \
    --backend "${tier}" --no-collect-counters --lock-clocks \
    --output-dir "data/outputs/mi300x_stage3b_final/${tier}"
done

# 3. 定向采集关键原语 rocprofv3 硬件计数器（可选全量加 --collect-counters）
python3 -m scripts.mvp_v1.cloud_runner \
  --mode full --device cuda:0 --target-override MI300X --backend aiter \
  --collect-counters --no-lock-clocks \
  --workload-filter "skinny_gemm_fp8_m16_n4096_k7168,mla_paged_decode_bf16_b8_kv4096" \
  --output-dir data/outputs/mi300x_stage3b_final/pmc_sample

# 4. 生成三层纵向对比表并执行 Hard Evidence Gate 校验
python3 -m scripts.mvp_v1.cloud_runner --compare \
  data/outputs/mi300x_stage3b_final/portable/summary.json \
  data/outputs/mi300x_stage3b_final/vllm/summary.json \
  data/outputs/mi300x_stage3b_final/aiter/summary.json

uv run python -m scripts.mvp_v1.cloud_preflight verify \
  data/outputs/mi300x_stage3b_final/vllm.tar.gz \
  --expected-sha256 be999975a263eb5d665f454816e6be116d9d55adf6e51de1b9d25be733222896
```
